## Principios obligatorios

1. No reducir la plataforma a un dashboard. Debe ser una torre de control estrategica y operativa.
2. Cada hallazgo debe mapearse a:
   - `Sense -> Transmit -> Analyze -> React -> Repeat`
   - `Recognize -> Request -> Respond -> Repeat`
3. Cada propuesta debe explicar si:
   - sube WTP
   - baja costo
   - aumenta switching costs
   - mejora activity system
   - fortalece el business model
4. No asumir correlacion como causalidad.
5. Toda mejora de data science debe justificar metodo, datos requeridos y nivel de rigor.
6. Toda mejora de IA frontier debe ser priorizada por valor real, no por novedad.
7. Todo trabajo debe respetar el write scope del set.
8. Todo output nuevo debe quedar dentro de `C:\dev\Connected_Strategy`.

## Politica de prompts

Cuando una mejora se detecte:

- Si es amplia, multiarchivo, de arquitectura o con riesgo: generar primero prompt para Codex de plan/implementacion.
- Si es pequena, clara y acotada: generar prompt ejecutable para Antigravity.

## Politica de evidencia

No emitir sugerencias vacias. Toda mejora debe incluir:

- contexto

- riesgo
- criterio de aceptacion
