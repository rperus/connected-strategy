## 3. Detalle de Hallazgos (P0s / P1s) y Safe-Fix Plan

### 🔴 P0: El Asesino N+1 en Endpoints de Métricas y Health
**Ubicación:** 
- `c:\dev\Connected_Strategy\apps\server\src\modules\health\routes.ts` (Línea 92)
- `c:\dev\Connected_Strategy\apps\server\src\modules\metrics\routes.ts` (Líneas 133-134)

**Impacto:** 
Dado que `better-sqlite3` es síncrono, ejecutar un loop iterativo que llama a `listAnswers(id)` (la cual hace `db.prepare('SELECT...').all()`) bloqueará el *Event Loop* principal de Node.js. El comentario en código sugiere que se hizo un "batch", pero el código hace `allProjectIds.flatMap((id: string) => listAnswers(id)...)`, lo cual es la ejecución de N consultas de DB (una por proyecto).

**Safe-Fix Plan:**
1. Crear una función `listAllAnswers()` en `worksheets.ts` (`SELECT * FROM worksheet_answers`).
2. En `health/routes.ts` y `metrics/routes.ts`, invocar `listAllAnswers()` una SÓLA vez y agrupar en memoria (`groupBy(projectId)`).

### 🔴 P0: Drift y Tablas Fantasma en Migraciones e Indexación
**Ubicación:** 
- `c:\dev\Connected_Strategy\apps\server\src\db\index.ts` (Línea 126)
- `c:\dev\Connected_Strategy\apps\server\src\db\migrate_tenants.ts` (Líneas 16-17)

**Impacto:** 
En `index.ts`, se intenta ejecutar `CREATE INDEX IF NOT EXISTS idx_telemetry_project ON telemetry_events(project_id);` durante la inicialización principal (`migrate(db)`), pero la tabla `telemetry_events` no se crea ahí, sino localmente en `services/telemetry.ts`. Si `index.ts` corre primero (que lo hace), lanza "no such table: telemetry_events". 
Adicionalmente, `migrate_tenants.ts` asume que existe la tabla `llm_cache` y altera su schema, pero la tabla no existe en el repositorio.

**Safe-Fix Plan:**
1. Mover el esquema `CREATE TABLE IF NOT EXISTS telemetry_events...` hacia la función central `migrate()` en `index.ts`.
2. Remover referencias a `llm_cache` o crear la tabla explícitamente en el inicio de SQLite.

### 🟡 P1: Schema sin Versionar (Migraciones Inline y Silenciadas)
**Ubicación:** `c:\dev\Connected_Strategy\apps\server\src\db\index.ts`
**Impacto:** Los comandos `ALTER TABLE ... ADD COLUMN` se están ejecutando dentro de bloques `try/catch` vacíos. Esto oscurece errores potenciales al fallar una migración y es un patrón anti-integridad.
**Safe-Fix Plan:** Integrar una tabla `_migrations` sencilla que lleve cuenta de un id secuencial, en vez de abusar de SQL exceptions controladas.
